Goal: The flag is being encoded through elliptic curve point multiplications and masking. We need to break the encoding to retrieve the original flag.

The challenge involves an elliptic curve defined over the finite field , where is supposed to be a “strong prime.” The flag bytes are converted to elliptic curve points and then obfuscated using a random scalar and a mask. Our goal is to recover the original flag from this transformation.

Analyse

Key Points

1. Elliptic Curve: The curve used is defined by the equation . The challenge gives the assurance that the curve’s order is a prime number (assert E.order().is_prime()), which implies that all non- zero elements of the group are invertible. This property will be crucial when trying to undo the multiplication by .

2. Prime Field used: The value of is written as 2^222 - 117. This suggests a prime number used as the field modulus. However, a common pitfall in Python is that ^ denotes bitwise XOR, not exponentiation. Therefore, the value of as written in the code is not as large as expected. Instead of being around , it becomes a much smaller number, making discrete logarithm attacks feasible.

3. Point Lifting and Masking: For each byte of the flag, the script attempts to “lift” the byte into an elliptic curve point using E.lift_x(). After that, the point is multiplied by and the coordinate is masked using 0x1fffffffffffff. The process is repeated until the byte can successfully be lifted.

How to solve

Recovering

To solve this challenge, we need to reverse the process:

1. The first step is to retrieve the random scalar . Since we know that the order of the curve is prime and every element is invertible, we can compute the inverse of if we can determine it.

2. We also know a part of the flag structure, such as that it begins with "3C{". This information helps us guess one of the bytes and use it to compute . Specifically, by lifting the known byte and comparing the result to the output from the script, we can perform a discrete logarithm to recover .

3. Once we have , we can reverse the point multiplication and retrieve the original flag bytes.

Solve script

python
from sage.all import *
from Crypto.Util.number import long_to_bytes, inverse, bytes_to_long
from random import randrange

p = 2^222 - 117  
F = FiniteField(p)
E = EllipticCurve(F, [0, 1, 0, 1, 3]) 

assert E.order().is_prime()

outputs = open("output.txt", "r").readlines()
ciphered = [int(x.split(": ")[1]) for x in outputs]
added = [int(a.split(": ")[0]) for a in outputs]

mask = 0x1fffffffffffff

# # Perform discrete log to recover r using known part of the flag 
xP = bytes_to_long(b"3") + added[0]
unmasked_x = F(ciphered[0]^mask)
unmasked_Q = E.lift_x(unmasked_x)
r2 = discrete_log(unmasked_Q, E.lift_x(F(xP)), operation="+")

# Brute-force method to recover r and reconstruct the flag
for r in range(1, p):
    flag = b""
    try:   
        for i, x in enumerate(ciphered):
            unmasked_x = F(x^mask)
            unmasked_Q = E.lift_x(unmasked_x)
            r_inv = inverse(r, E.order())
            P = F(r_inv) * unmasked_Q
            x_value = F(P[0]) if F(P[0]) > 40 else int(P[0]) + p
            flag += long_to_bytes(int(x_value) - int(F(added[i])))
        if b"}" in flag:
            # Verify that both methods give the same result
            assert r == r2
            print(flag)
            exit()
    except ZeroDivisionError:
        continue
